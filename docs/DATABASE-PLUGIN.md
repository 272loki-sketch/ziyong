# 原数据库插件接入（本地 v1.8.10）

## 原版文件与宿主兼容边界（2026-10-08核对）

**原插件安装文件未修改，不等于原执行环境和全部行为零差异。** 当前不是完整 `git clone` 后自行编译运行，而是下载用户指定的 `naiv1.2.4/index.js` 打包安装产物，校验后从私有缓存原样加载。生产缓存8,721,856字节，SHA-256为 `ff8981ea9f60bbada765ce79d576bf84963e842c12b683feb6e8fe22b74b8bac`；Git blob SHA-1为 `191d6651b34e700b025a075f18b0deece51a1c21`，与已核验的固定上游仓库对象一致。这个证据只证明该文件未改、未重新打包，不证明宿主百分之百复刻原酒馆。

原脚本的UI、填表、交火检索、原生记忆任务和最终输入模板由原字节执行。以下部分则是梨园自己的宿主实现，不能称为上游原实现：

- 在隔离浏览器中提供 `SillyTavern` / `TavernHelper` 接口与聊天事件；支持面和事件时序由适配层提供，不是直接运行完整酒馆服务。
- 初始化/一次性迁移插件开关、0TK/填表模式和模型预设，将原模型请求路由到已配置连接；这会影响运行配置，但不修改上游安装文件。后续用户手动设置保留。
- `src/stage/database-plugin-prompt.ts` 实现世界书关键词激活、递归和position/depth/order/role投送。它是宿主兼容代码，不是从酒馆导入的完整世界书引擎；支持的字段有回归，不支持的位置明确报错，尚无完整原酒馆黄金对照，不能宣称所有语义等价。
- 原卡/挂载书只读，存储、文件、取消/恢复和来源保护按梨园会话/分支实现；部分无关接口为兼容占位或受限支持，原插件独立正文续写/推演不自动作为第三个作者启用。

v1.8.9曾通过宿主强制关闭原召回、再自行拼接记忆，属于实际执行行为偏离，不能以“源码文件没改”掩盖。v1.8.10已撤掉这条替代路径并接回原召回/写回，但上述宿主差异仍然存在。测试结论只能覆盖列明用例；维护时不得再将“原文件一致”或“用例通过”写成“全部执行逻辑从未改变、百分之百原生等价”。

## 原生发送前召回与写回（v1.8.10）

用户输入先按原文落Session Tree，然后后端调用未修改的原插件 `TavernHelper.generate` 拦截器。交火准备、原剧情记忆召回任务、AM选择、标签提取、最终指令模板与写回顺序均由上游执行；梨园捕获拦截器实际交给宿主的 `user_input`，逐字传给正文模型。原模板可在包裹的本轮用户输入之后追加 `<recall>` 等任务结果，不由梨园另写模板或把它改成前置「剧情记忆」。原用户记录不被写回内容污染。

之前宿主将 `plotEnabledGlobal` 强制关闭，误把原生召回任务当成第三个故事作者，并自行从禁用纪要索引取AM、裁剪条目、拼接【剧情记忆】；v1.8.10纠正这条偏离。旧适配一次性恢复原生召回入口，绑定现有召回3.8 Flash预设，此后保留用户手动开关/预设选择。不修改原任务提示词、提取规则、最终模板或素材。原插件独立续写/格林推演不作为第三个正文作者启用；这与原生发送前记忆任务是两回事。

世界书适配仅承接宿主协议：按原 `enabled/type/keys` 及普通关键词递归激活，保留原包装、完整内容、`position/depth/order/role`；禁用的0TK目录不会成为宿主的隐藏AM筛选入口。before/after-character进入预设原世界书/角色槽位，深度条目按原深度单独进入消息流。没有额外的记忆概括文案或宿主字符截断，旧 `injectionMaxChars` 配置字段仅为兼容保留，不再裁剪原插件条目。

正文模型传输层必须保留这些深度消息：OpenAI兼容chat-completions与Responses支持原位置system消息；Mistral也保留inline system；原生Google/Anthropic/Bedrock接口若不能表达inline system则明确报不支持，不默默忽略、改角色或移到顶部。当前配置的Gemini走OpenAI兼容连接，原作者/填表/召回角色与密钥位置不变。

导演与直出共用同一个原生准备/写回入口、世界书投送与拍后整理。导演专家/正常文学导演读取同一份上游结果作为参考，不另选AM。记忆任务产物不是已发生事实，正文仍由单一主作者提交；取消、切分支和pending恢复边界保留。

本次证据与限制见 [原生召回验收](VALIDATION-DATABASE-v1.8.10.md)。v1.8.9三次实战证明当时的适配可召回，不证明它与原发送前写回流程等价；不得把旧实战报告当本次修复的原生链路实测。

## 采用方式

使用用户指定的 AlbusKen/shujuku `naiv1.2.4` 安装脚本，原样私有缓存，不fork或把无明确整体授权的上游产物复制进公开源码/发行包。固定SHA-256为 `ff8981ea9f60bbada765ce79d576bf84963e842c12b683feb6e8fe22b74b8bac`。已按Git blob核对CDN产物；来源名/版本、指纹与上游更新候选可在设置面板查看。

梨园只维护宿主适配：模型调用、当前分支聊天、metadata/settings、世界书、私有文件与生命周期。原人物表、纪要、填表解析、索引、交火BM25/向量融合、0TK和原管理台继续使用上游实现。插件的独立剧情代写/推演不作为第三种正文模式；direct/director与原作者卡格式不变。

## 事实和隐私边界

- `Session Tree/rpNarrative`仍是故事事实。只提供规范正文；作者原交付、thinking和工具回执不作为正文传给插件。
- 插件的消息扩展只允许 `TavernDB_*`，不允许写mes、rpNarrative或思考；会话＋卡作用域、sourceEntryId与revision/CAS保护迟到提交。读状态只取当前祖先来源，兄弟分支不可见。
- 插件生成的世界书是专用派生书。原卡/挂载书供读取，不允许插件改写生产PNG或复活关闭条目。0TK控制目录常驻，宿主按原关键词与位置投送激活条目的完整原文，不从禁用目录补选AM或自行截断。
- `.liyuan-database-plugin/`0700、文件0600；包括状态、设置、向量、上游缓存与私有依赖，不入Git/发行包。外置对象使用内容寻址blob与来源指针，读取只查祖先来源，分支删除用tombstone，不删除其他分支仍引用的对象。API Key沿用服务端记忆岗位和独立嵌入配置，不通过宿主context返回真实Key；上游存量设置里的嵌套/JSON字符串密钥和URL查询凭据下发时掩码，掩码回写保留服务端原值。
- 普通配置后台角色仍按原岗位解析，不统一换GPT；自定义向量/重排仅代理已保存HTTPS连接，拒绝私网/回环及任意地址。

## 时序与恢复

启用插件时旧自动周期正文入库、旧事件提取、旧摘要压缩关闭，但旧SQLite和摘要原文不删除。作者保留最近有界正文，长期资料由原插件提供；旧分支已有摘要仍作为只读迁移资料保留，不继续运行旧摘要模型，也不默默抹掉旧会话的重要前情。历史纪要大规模补填使用原管理台批量功能，不自动发起高额全量复盘。正常拍保存事实后调用原插件 `triggerUpdate`，写完整的原插件V2帧并生成世界书；源收据为 `rp-database-memory`。

失败标pending，不假称入库成功；下一拍先恢复旧source，再准备新记忆。已保存同source帧去重，不重演故事。取消关闭在途浏览器任务；切卡/分支丢弃迟到写入。手动资料落插件派生书，不混入自动故事事实，生成表行需从原管理台管理。

## 管理与更新

主界面的「数据库」入口打开居中弹窗管理台，直接自动打开原插件完整前端；也可从设置→上游数据库插件打开同一弹窗，或新标签独立打开。人物表/纪要在原「可视化表格编辑器」中管理，原仪表盘、填表模式、API、数据管理与高级工具保留，不重做上游界面。关闭弹窗返回原对话，不重建会话。切卡/会话/分支会重新绑定管理宿主（独立新标签同样跟随当前作用域）；轻量绑定查询只返回身份与运行状态，不重复下载几千楼正文或全部世界书。加载、缺少源码或打开失败有明确提示与重试，iframe载入不假称管理界面已就绪。

设置→上游数据库插件：启用/回退旧后端、固定源码安装、检查更新和回退上一版本。检查更新只看已知仓库，验证Git对象与CDN字节，再生成commit固定地址和SHA-256；不自动激活不明新版本。安装成功保留前一指针；失败不覆盖有效缓存。上游候选升级仍需隔离验收，不声称版本永远兼容。

首次加载会为宿主配置独立记忆模式：有云端嵌入时交火、否则经典表格；0TK开启，独立正文续写不自动启用，原生发送前召回任务保留。上游可能按它自己的迁移规则刷新召回默认值，不能把宿主初值冒称固定上游默认。两千纪要浏览器回归已覆盖真实填表、持久化、世界书投送、交火嵌入代理、0TK目录关闭、同source恢复去重与兄弟隔离；模型/嵌入是合成响应，不等于真实千楼文学答对率。

## 运行依赖

服务端用Playwright运行原浏览器插件，不要求用户一直开着网页；Chromium及其运行库需要部署者安装。可设置 `LIYUAN_DATABASE_BROWSER_EXECUTABLE` 和 `LIYUAN_DATABASE_BROWSER_LIBS`。浏览器只允许同源宿主请求，外部模型由服务端代理。首次安装的jQuery3.7.1与sql.js1.14.1私有依赖缓存由维护流程核验；不把它们或插件字节当本项目源码发布。

测试命令：`npm run test:database-plugin`；`npm run test:database-plugin-browser`需要显式合成缓存路径，未提供时只报跳过，不假冒端到端成功。完整离线门禁仍为 `npm run verify`，不等于真实模型、全后端tsc或三平台发行。

独立前端验收：`npm run test:database-plugin-manager` 需要显式合成源码/vendor与候选dist；未提供时明确跳过。管理宿主以 `?view=manager` 选择展示模式并调用原公开 `AutoCardUpdaterV2API.open()`，后台默认宿主不自动开管理窗口。宿主JS使用构建版本查询参数且服务端no-cache，避免旧适配代码被浏览器长期缓存。


## API预设和模型角色（v1.8.9）

原插件的 `POST /api/backends/chat-completions/status` 与 `generate` 已接入梨园：模型列表会真正访问上游 `/models`，不是伪造连接成功；生成支持原OpenAI兼容JSON、工具调用结果和完成式SSE协议。已启用的梨园连接使用宿主引用，API Key留在服务端，不要求再次把真实Key粘贴到前端。独立自定义API支持原UI的模型查询、保存、YAML附加请求体和排除字段；未绑定的新地址限公网HTTPS，并固定检查过的DNS地址，拒绝重定向与私网访问。私人网关仅在梨园已明确启用该连接时复用。

数据库配置独立保存 `fillModel` / `recallModel`。本次按用户明确要求，填表、召回使用现有 `gemini-3.8-flash`，嵌入连接和其模型保持原配置。原API页面可见「梨园 · gemini-3.8-flash · 填表／召回」预设；后续用户手动改选不被每次打开强制覆盖。默认主作者、其它岗位与生成模式不随这个选择改变。

预设凭据回写按稳定预设和端点身份匹配，不能因数组删除或重排把A密钥交给B；端点变化不会继承旧Key。带缩进的鉴权请求头同样掩码。状态和模型调用在异步等待之后重新检查scope/source；请求进行中也会因绑定变化取消。状态头只在最终绑定检查后原子发布，迟到请求不能变成另一分支的新记忆。

原API与旧版三次连续实战见 `VALIDATION-DATABASE-v1.8.9.md`；原生召回写回、v1.8.10门禁和部署见 `VALIDATION-DATABASE-v1.8.10.md`。未覆盖的原插件独立正文续写/格林推演仍受梨园两模式和正文权威边界限制，不作为第三个作者启用；原生发送前召回任务不是独立正文作者。
