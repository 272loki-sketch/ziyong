# 当前卡的完整格式交付

## 契约

直出与导演的差别是创作思考分工，不是资料或输出能力。两者读取同一启用角色卡、世界书、原始预设、用户身份、当前分支、记忆和已提交状态；正文保存后共用完整格式交付与失败恢复。不同卡的面板、标签名、HTML、Markdown、JSON及排列由主Agent读原文决定。

跨卡固定的是**行动选项**和**正文中穿插的图片提示词块**。图片块生成不等于位图已生成，外部NAI绘图仍由既有媒体配置和显示行为决定；只读实战记录不会自动启动生图。

## 工件与权威

| 工件 | 内容与边界 |
| --- | --- |
| `details.rpNarrative` | 已保存故事事实，不把图片提示词、选项、论坛和附属状态当作主故事事实 |
| `details.rpAuthorDraft` | 同主作者的完整原交付，供格式恢复和原始核对，不是第二份故事权威 |
| `rp-presentation-delivery` | 绑定`targetEntryId`的自由布局、图片、卡格式、需求/检查及输入计数；是展示工件 |
| `rp-turn-settlement.presentationDone` | 交付是否完成；失败为pending，不用只剩正文冒充整拍完成 |
| 安全Wire `presentationDelivery` | 有限状态、来源数、字符数、重交次数及格式名称；不传prompt、专家报告或原始来源正文 |

格式工件只能绑定当前分支已保存正文。显示回放再次核对故事文本一致；回档只消费当前祖先链，不拿别的分支或角色卡工件覆盖。状态栏、小剧场和备选行动不会反向写入剧情账本。

## 一拍中的位置

1. **装配**：正常卡资料、原始预设和启用世界书；两模式不裁减这份主作者材料。
2. **写作**：直出经过正常文学导演后由单主Agent交付；导演经过固定3证据/2角度/草稿/2审阅/取舍定稿。原作者输出完整保留，图片不再被纯正文清理不可逆删除。
3. **卡自定义正文边界**：已知正文容器直接解析；未知XML/HTML/JSON结构由同主作者逐字引用自己已写的故事片段，不能重新编写或概括。附属展示不成为主正文。
4. **正文保存与事实结算**：角色账本、启用的世界/生态按既有事实、来源、审计和分支门禁提交。
5. **格式需求识别**：同主Agent逐份读取原始格式定义，判断本拍条件、列出自由需求及出处。每份候选定义要有`sourceReviews`，同一文档里的多项要求分别登记。没有固定“某卡六面板”清单。
6. **完整交付**：主Agent按需求生成任意卡格式，并决定正文、图片与各格式的前/中/后位置；宿主依给出的顺序展示。
7. **校验与保存**：原文引用、图片位置、实际选项、需求标记及闭合块核对。失败反馈给同主作者有限重交；仍失败留pending，不跳过或假成功。

两模式都执行5–7；直出不是“只保留纯文字”。格式轮正常采用结构化文本收据，这是任务协议，不是工具不支持的降级。

## 材料传递

`src/stage/agent-presentation.ts`提供：

- 原卡说明、性格、场景、系统/历史后指令、示例及开场资料；不开送完整原卡JSON中的大体积插件脚本。
- 当前启用世界书的索引、常驻/相关资料与格式候选定义；已选定义原文完整，不沿用6000字符/累计24K的静默格式裁剪。
- 启用预设的格式/输出原文、显示正则入口提示、当前用户输入、人设、冻结正文及最终已提交状态。
- `sourceIndex`可供Agent请求尚需读取的原文；读取受当前启用范围、分支和有限次数约束。

候选识别规则只帮助找**来源**，不是许可输出标签白名单。源原文中声明的任意标签或无标签格式都可交付。显示皮肤的正则表示“能够显示某种格式”，不能用来复活关闭的世界书模块。

## 原文引用布局

为避免重复打印长正文而改词、夹带时间抬头或生成截断JSON，优先引用宿主提供的`frozen_segments`与`authored_images`：

```json
{
  "layout": [
    {"kind":"format","text":"原卡要求的正文前容器或标题"},
    {"kind":"narrative","refs":["n:0","n:1"]},
    {"kind":"image","ref":"image:0"},
    {"kind":"narrative","refs":["n:2"]},
    {"kind":"format","text":"原卡要求的其余任意格式"}
  ],
  "requirements": [
    {"id":"本拍需求ID","name":"该卡格式","kind":"card-format","quote":"实际交付片段"},
    {"name":"行动选项","kind":"actions","quote":"实际选项片段"}
  ],
  "missing":[]
}
```

- 正文引用必须原序、完整、一次；已有完整图片的内容与先后次序保留，新图片才生成提示词块。
- 图片必须前后都有叙事，全部堆在正文末尾不等于穿插。
- 时间抬头、可见标题与其它附属文字放`format`，可与正文自由混排，不能污染冻结正文。
- `requirements`引用实际交付而非“已完成”声明。原规则明确标签/稳定标记时，由Agent登记动态`locator`，代码核对真实块；不在代码枚举面板名称。
- 文本型`body`/`formats`收据仍可解析兼容，但与引用型遵守相同事实和交付校验。

校验不是文学评分，也不证明模型没有遗漏条件理解。源引用、逐来源清单、实际块和可见记录是互补证据，不能据工程通过宣传全部卡或所有格式普遍通过。

## 失败恢复

- HTTP鉴权、模型、限额、超时/传输和格式错误分别诊断；不支持工具是另一条能力判定。
- JSON无效或交付不合格有明确回执，有限重交/结构修复后重新执行原校验，不由代码补写剧情或瞎造格式。
- `presentation`失败记为待恢复；新输入前或手动重试只恢复未完成部分，不能重复推进已提交世界/生态或重演正文。
- 格式重Roll复用同一自适应链。新结果无效时保留原工件并明确报错，不用坏结果覆盖可用格式。
- 分支改变、取消与迟到结果仍丢弃；打开只读记录不切卡、换会话或调用模型。

## 兼容范围

没有显式`generationMode`的旧SDK稿纸路径暂保留旧`curtain-materials.ts`严格标签/原生日历行为；新Web两模式不使用其白名单收口，也不叠加原生日历来替代卡自己的日历。旧实战里的失败、截断、额外格式不改写成新契约成功样本。

代码与提示词入口：`agent-presentation.ts`、`engine.ts`、`agent-turn.ts`、`server/main.ts`、`server/wire.ts`，以及`卡格式需求识别`、`卡格式完整交付`、`主作者正文边界`三个Skill。主作者职责由原始预设决定，系统没有新增主角授权或固定小说结尾规则。
