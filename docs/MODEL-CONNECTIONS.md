# 模型连接、岗位与Luna命名

## 不合并模型分工

模型目录来自当前启用配置，保存的历史配置不是自动可调用渠道。默认模型和 `stepModels` 是不同设置；连接页选择与岗位覆盖需分别核对，不能显示已换模型却仍调旧覆盖。

**Gemini 3.7 Flash、Gemini 3.8 Flash各自正常运行，保留原配置和岗位。** 此前仅将Luna旧名迁移至 `gpt-6-luna`，不把作者、专家、世界、生态或记忆岗位全部改为Luna，不打开旧仓库渠道。

## Luna原生入口

已验证支持新名称的CLI Proxy API作为单独Luna渠道，当前既有Flash渠道保持不变。现用旧外层中转尚未发布新ID，不能把它的请求ID直接替成6而期待可用。旧5.6兼容入口不再作为当前配置依赖；不要恢复过期模型名。

不得把API Key、OAuth认证、私有网关地址、SSH密码或私人配置写进公开文档/提交。保存前后核对Flash模型定义、默认主演和全部Flash岗位；模板使用占位符，而不是某个用户的服务器。

## 传输修复

CLIProxyAPI v8.0.8首字前等待发生在返回流渠道之前，普通流中保活覆盖不到。基于同版本的首字等待dispatch补丁，SSE注释/非流式空白行每15秒保活，对应反代即时flush，取消和迟到错误保留。

真实公开Cloudflare合成135秒对照：原版125.275秒524；修复后的首字流式、非流式、流中静默均完整200，原生工具未丢失。真实短工具请求验证Luna6，不用大段剧情做付费压力测试。此修复不意味着配额或任何供应商真正截止都消失。

## 手动声明工具调用能力

连接页的**每个模型**都有“支持工具调用”复选框。新配置/新模型默认勾选；不能使用原生工具的 API/模型取消勾选即可。已经明确配置为关闭的旧条目不会被自动重新开启。

- **当前生效**区域的开关直接保存，并同步启用中的配置仓库；后续请求使用新能力。正在运行的一拍使用其已捕获的模型配置，不追改本拍。
- **配置仓库 → 修改**可以分别设置清单中的模型，点击“保存修改”。启用中的配置以当前启用范围为基底，保存即同步运行时，不用旧单渠道副本覆盖其它已启用渠道；未启用的配置仍只留仓库。
- **配置生成器**中同样可逐模型勾选。生成/保存配置不自动启用，也不切换当前模型。

设置存放于 `providers.<渠道>.models[].compat.supportsTools`：取消写 `false`，重新勾选写 `true`。模型级值覆盖渠道级 `compat.supportsTools`；两级都未配置时默认支持。已有渠道级关闭会显示为未勾选，重新勾选明确写模型级 `true`，不会误删渠道的其它兼容参数。

关闭只禁用该模型的**原生工具协议**：实际主演请求不附 `tools`/`tool_choice`，不靠先报错重试探测。不切换模型、岗位或生成模式；director仍执行固定3证据/2角度/2审阅，主Agent通过文本流程作出定稿决策。依赖原生工具的资料读取/MCP/媒体操作不会被假装执行；已有结算旁路仍按自己的岗位配置运行。模型的流式、思考、容量、其它兼容字段以及其它渠道保持原样。

该勾选是用户声明，不是自动能力测试；上游即使勾选也可能因配额、参数/schema或网络失败。参数错误和超时不等于“不支持工具”。当前模型快改在有启用仓库时通过一次仓库保存同步运行时，没有启用仓库时直接保存运行配置。保存失败会报告错误；若服务器已写入但响应丢失，界面重读真实保存状态而不显示虚假的成功提示。

## 兼容与预算

支持能力须由该端点明确配置或原生请求验证，不能只看模型家族名。未知reasoning_effort/developer角色参数不强开，schema或HTTP错误不是“不支持tools”。整拍预算和代理空闲窗口不同；自动重试有界，错误如实记录。
