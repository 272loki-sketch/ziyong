# 当前剧情记忆、摘要与证据系统

适用现行普通文本主Agent的 direct/director。记忆服务 `src/memory/` 使用 SQLite，不是另一套正文或世界状态。

## 1. 权威与作用域

- Session Tree上的已提交 `rpNarrative` 是故事事实；`rp-state`、世界/生态和大纲分别负责对应已确认状态。
- `rp-summary` 是早期剧情的接力摘要，不能覆盖当前分支事实。事件卡是定位/检索投影，证据归档提供原文细节。
- 库作用域绑定会话＋规范化卡路径；读取再按当前祖先链校验sourceRefs，兄弟分支不可见。
- 手工记忆写额外库，不能把候选建议当已发生剧情写入自动剧情库。

## 2. 实际存储和配置

`src/memory/store.ts` → `.liyuan-memory/memory.sqlite`，WAL事务、来源元数据、diff记录和串行写锁。旧JSONL按作用域惰性迁移，不删除用户原始内容。

配置含总开关、`injectOnTurn`、嵌入模式、检索条数、库开关、剧情周期与容量、计数器和事件游标。嵌入是独立配置，不随主演、Flash或Luna切换。

- local：本地256维哈希嵌入，不调用云端。
- cloud：配置的OpenAI兼容embedding服务。模型、维度和模式必须与存量向量一致；检索拒绝跨空间混算。切换后用明确的“重建向量”，不自动收费重嵌入。
- narrative：正文周期片段、事件卡、压缩证据；默认小容量，按优先级淘汰，核心事件受保护。
- external/custom：用户资料和手工内容，按会话/卡分库。

## 3. 写入时序

### 周期正文

`server/main.ts onTurnEnd` 捕获本拍session/card/sourceEntryId和分支快照，由 `narrativeMemoryWindow` 提取最后N个成功正文拍及其用户输入。新模式只取 `rpNarrative`，不把 `rpAuthorDraft`、布局、thinking、工具结果、开场或未完成拍当正文。

到达 `everyNTurns` 才写窗口，每块带entryId、绝对拍号、字符范围、分支叶和 `textBasis`。未到周期只更新计数；保存失败不假报成功。模型报告的事件提取另有游标：全部目标入库后才推进，失败下窗口可重试。

### 事件卡

`StageEngine`按周期调用记忆Skill，事件id由代码按会话/卡/来源生成。core/major优先、`op=create/skip/merge`有边界，不能跨兄弟分支盲合并。总开关关闭时不调事件模型。

### 长局压缩

`src/stage/compact.ts` 自动压缩条件：周期＋足够早期正文；最近6拍保留，摘要覆盖明确截止条目。摘要落树前归档被裁正文和来源，旁路期间切支则丢弃。新格式正文与原交付分开，证据偏移以明确文本基准回源；旧记录仍按原entryText基准读取，不篡改历史缓存。

## 4. 读取时序

- 普通继续：已有摘要/状态＋活跃剧情线投影，不无条件对所有历史做昂贵向量查询。
- 明确历史点：query → 事件/片段 → sourceRefs原文证据；拍前有限等待，失败回到摘要/现有状态。
- 作者可用 `memory_search` 主动查缺失细节。无命中不应编造已发生事实。
- 缺来源的旧记录是旧数据，不是可靠source-backed证据。管理查看与自动召回应区分。

## 5. 如何判断“在运作”

检查四层，不只看enabled：配置和目标scope、成功正文拍数/周期、嵌入连通和向量空间、真实写入/来源/召回记录。

当前空会话或只有失败输入时0条是正常；不切换成别的会话来凑“成功证据”。检查会话用真实条目timestamp和id，不用文件mtime。生产只读，不人为注入测试事实。

验证：`test/memory*.test.ts`、`rp-memory*.test.ts`、`stage-compact.test.ts`。云端金丝雀使用独立临时库和合成文本，证明写入→查询→兄弟分支隔离；不调用聊天模型或写生产库。

## 7. 关键事件与人物经历的提示词合同（源码调整，完整接线待重启核验）

本次按用户要求由主助手亲自修改记忆提示词，Luna只独立审查。目标不是全历史逐字找回，而是关键事件、主要人物和重要配角的重要经历可被长期接力与按需定位。

- 事件筛选检查经历、选择、关系变化、承诺实际结果、身份与知情变化；日常形成重要共同经历时也可记，不设建卡配额，不把所有日常抬为核心事件。
- 同一事件的补充才merge；同一剧情线的新阶段以独立事件和已有links连接。已解决或人物离场不等于历史不重要，摘要保留起因—行为—结果，不只留下最新关系标签。
- 初建/增量摘要继续使用十节v2结构；Characters增加重要经历，兑现/违约/取消从未决清单移入历史结果，压缩普通重复而非删除久远的重要人物。摘要目标长度不是硬删阈值。
- 现行memory Skill经原用户覆盖解析后传入摘要。规范新模式在调用前提供正文与真实entry来源映射，避免要求模型猜entryId；正文只发送一份。此来源模式下，新增事件没有有效来源或范围为空时拒绝摘要，不用整个窗口补造证据；旧SDK补丁/导入或超大窗口仍走旧序列化兼容路径，不重写旧记录。摘要envelope的links只使用已提供的已有canonical id，未接线的同批sourceKey目标不作为新提示词要求。
- 召回查询使用人物＋具体事件/物品＋已知时间地点/所问结果；不等用户明说“还记得”才核对，也不强制每拍查询。结果区分事件概括与原文证据，保留已知人物/时间/地点辨识信息。
- 无命中仅表示检索缺口，不能写成事件未发生、角色失忆、违约或关系变化。作者所知与角色所知分别核对，概括不能冒充逐字原话，时间相邻不能升级为因果。
